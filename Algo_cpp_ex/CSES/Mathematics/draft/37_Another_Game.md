# Another Game

## Problem Description
There are $n$ heaps of coins and two players who move alternately. On each move, a player selects some of the nonempty heaps and removes one coin from each heap. The player who removes the last coin wins the game.
Your task is to find out who wins if both players play optimally.

有 $n$ 堆硬币，两名玩家轮流行动。在每一步行动中，玩家选择一些非空的硬币堆，并从选中的每一堆中移除一枚硬币。取走最后一枚硬币的玩家赢得游戏。
你的任务是找出在双方都采用最优策略的情况下，谁会赢得游戏。

## Input
The first input line contains an integer $t$: the number of tests. After this, $t$ test cases are described:
The first line contains an integer $n$: the number of heaps.
The next line has $n$ integers $x_1, x_2, \ldots, x_n$: the number of coins in each heap.

第一行输入包含一个整数 $t$：测试用例的数量。之后描述了 $t$ 个测试用例：
第一行包含一个整数 $n$：硬币堆的数量。
下一行包含 $n$ 个整数 $x_1, x_2, \ldots, x_n$：每一堆中的硬币数量。

## Output
For each test case, print "first" if the first player wins the game and "second" if the second player wins the game.

对于每个测试用例，如果先手玩家获胜则输出 "first"，如果后手玩家获胜则输出 "second"。

## Constraints
* $1 \le t \le 2 \cdot 10^5$
* $1 \le n \le 2 \cdot 10^5$
* $1 \le x_i \le 10^9$
* the sum of all $n$ is at most $2 \cdot 10^5$

## Example
**Input:**
```text
3
3
1 2 3
2
2 2
4
5 5 4 5
```

**Output:**
```text
first
second
first
```

## 算法原理解析

这道题目虽然披着博弈论的外衣，但在进行深度的树状递归推演之前，它其实隐藏着一个非常巧妙且唯美的规律，即基于**奇偶性（Parity）**的镜像复制策略。

**核心结论：**
* 如果**所有**硬币堆的数量都是**偶数**，后手（`second`）必胜。
* 如果**存在至少一个**硬币堆的数量是**奇数**，先手（`first`）必胜。

**严格证明：**

1. **全偶数状态属于必败态（后手必胜）：**
   假设当前面临所有堆的硬币数统统是偶数的局面。先手无论如何选择——哪怕是随机挑选任意个非空堆并各拿走 $1$ 枚硬币，这些被挑选出来的原本呈偶数个硬币的堆，都会因为被减去 $1$，而变成奇数堆。
   这个时候奇妙的事情发生了！后手只需要**照葫芦画瓢地完全模仿先手的动作**（先手选了哪几堆，后手就去选那对应的几堆，然后也各拿走 $1$ 枚硬币）。那么，这些前一回合被先手变成奇数的堆，又会被后手精准地变回**偶数**。
   只要后手一直作为复读机行使这个动作，先手每次回合开始时所面临的，永远都是一个令人绝望的“全偶数局面”。游戏结束的终点（所有堆清空为 $0$）本身就是一个“全偶数局面”，这就意味着取走最后一枚硬币的致命一击必然是落入后手的回合中产生的，所以后手必胜。

2. **存在奇数状态属于必胜态（先手必胜）：**
   如果初始状态存在至少一个奇数堆，面对这种局面的人掌握着绝对的主动权。先手只需要**精准地挑出所有的“奇数堆”**，然后在这几堆中各拿走 $1$ 枚硬币。
   这番操作好比魔法除尘，直接把所有的“奇数堆”强行削成了“偶数堆”！此时整个场上已经不存在奇数堆了，先手非常优雅地把一个“全偶数局面”扔给了后手。
   根据前面第 1 点的分析，面对全偶数局面的人是必败的。因此此时面对这个残局的后手必败，先手必胜。



   太棒了！经历过前面《Grundy's Game》那种深渊级别的异或与 SG 函数的洗礼，现在这道《Another Game》对你来说绝对是**“降维打击的甜点”**。

这道题**完全不需要异或，也不需要 SG 函数**。它回归了我们在讲阶梯博弈（Staircase Nim）时用过的最朴素、最无解的战略——**“学人精（镜像模仿）”**。

让我们用两分钟，直接看破这道题的底裤。

---

### 一、 规则与“终点”分析

**规则**：每次可以挑选**任意数量**的非空硬币堆，然后从被选中的每一堆里，**各拿走 1 个硬币**。
**终点**：所有硬币堆全变成 `0`，谁拿到最后一个谁赢。

我们来看看游戏的终点：`0, 0, ..., 0`。
0 是什么数？**0 是偶数。**
所以，游戏的终极目标是把局面变成**“全偶数状态”**丢给对手。

---

### 二、 逻辑推演（学人精战略）

我们根据硬币的奇偶性，把局面分成两类：

#### 局面 A：所有堆的硬币全都是【偶数】（必败态 L）
假设桌子上是 `2, 4, 6`。
轮到你了，规则要求你必须从这几堆里选出几堆，各减去 1。
*   你挑了第一堆和第二堆，各减 1。局面变成了 `1, 3, 6`。
*   **发现问题了吗？** 只要你动了偶数，减去 1 之后，它**必定会变成奇数**！
*   轮到对手了，对手怎么做？对手微微一笑，发动“学人精”技能：**你刚才动了哪几堆，我就跟着动哪几堆！**
*   对手也从第一堆和第二堆各减 1。局面变成了 `0, 2, 6`。
*   **奇迹出现了！所有的硬币又全部变回了偶数！**

**结论**：只要你接手时是**“全偶数”**，无论你怎么挣扎，你必定会制造出奇数。而聪明的对手只要永远模仿你（在同一个地方也减1），就能把局面再次恢复成“全偶数”。由于硬币越来越少，最终拿到 `0, 0, 0` 这个终极“全偶数”的，必定是对手！你必输。

#### 局面 B：至少有一堆硬币是【奇数】（必胜态 W）
假设桌子上是 `1, 4, 5, 6`（有两堆是奇数：1 和 5）。
轮到你了。你需要把一个必败局（全偶数）扔给对手。
你能做到吗？**太简单了！简直是量身定制的规则！**
*   规则允许你挑选**任意多堆**硬币。
*   你只需要把桌子上**所有是奇数的硬币堆，全部挑出来**（挑 1 和 5 这两堆），然后各减去 1。
*   奇数减 1 变成偶数。原本的偶数你没碰它，还是偶数。
*   局面瞬间变成了 `0, 4, 4, 6`。**全偶数！**
*   你成功把“全偶数”这个必死的烂摊子甩给了对手。

**结论**：只要桌上**哪怕只有 1 堆奇数**，你都可以通过“一次性把所有奇数堆各减 1”，瞬间将局面变成“全偶数”。你必赢！

---

### 三、 终极结论（一秒破题）

忘掉什么状态转移，忘掉什么异或和。

这道题的胜负只取决于输入数据里**有没有奇数**：
1. **如果有任何一个奇数**：先手大喊一声“把所有奇数全减1”，将全偶数丢给对手。**先手必胜（first）**。
2. **如果全都是偶数**：先手不管怎么动，都会造出奇数，后手只要当“学人精”就能恢复全偶数。**后手必胜（second）**。

---

### 四、 验证样例

用我们的“奇数雷达”去扫一眼题目的三个样例：

*   **Test 1**: `1 2 3`。有奇数吗？有（1和3）。**结论：first。**
*   **Test 2**: `2 2`。有奇数吗？没有（全偶数）。**结论：second。**
*   **Test 3**: `5 5 4 5`。有奇数吗？有（5）。**结论：first。**

完全一致！

### 五、 极简 C++ 代码

这可能是 CSES 博弈论题单里代码最短的一道题了。我们连数组都不用开，一边读数据一边判断就行。

```cpp
#include <iostream>

using namespace std;

void solve() {
    int n;
    cin >> n;
    
    bool has_odd = false;
    for (int i = 0; i < n; i++) {
        int x;
        cin >> x;
        // 如果发现哪怕一个奇数
        if (x % 2 != 0) {
            has_odd = true;
        }
    }
    
    // 有奇数先手赢，全偶数后手赢
    if (has_odd) {
        cout << "first\n";
    } else {
        cout << "second\n";
    }
}

int main() {
    // 快速 I/O 依然是好习惯
    ios_base::sync_with_stdio(false);
    cin.tie(NULL);

    int t;
    if (cin >> t) {
        while (t--) {
            solve();
        }
    }
    
    return 0;
}
```

### 总结

博弈论千变万化，并不总是需要套用 `SG 函数` 和 `异或` 的数学大招。
这道题提醒我们：**在拿到任何博弈论问题时，先不要急着写 SG 公式。**

第一步永远是**“观察操作规则和终点状态”**，寻找有没有类似于：
*   奇偶性维持（学人精）
*   对称性维持（两堆一模一样）

如果存在这种**“我可以完美复原你的破坏”**的逻辑闭环，那么这种题连算都不用算，单纯考察的就是逻辑思维的敏锐度！


这个问题问得太深刻了！你能问出这个问题，说明你没有在死记硬背，而是真正开始思考博弈论底层数学模型的**适用边界**了。

为什么这道题不能用 SG 函数和异或？为什么它和标准 Nim 游戏看起来很像，解法却天差地别？

答案只有一个：**这道题破坏了 Sprague-Grundy (SG) 定理的“绝对适用前提”。**

我们把这道题和标准 Nim 游戏放在显微镜下，对比它们规则里那**致命的几个字**的差异，你就彻底明白了。

---

### 致命差异：规则的“镜像反转”

仔细看这两者的游戏规则，它们完全是反过来的：

*   **标准 Nim 游戏**：每次只能选 **【1 堆】**，拿走 **【任意个】**。
*   **本题 (Another Game)**：每次可以选 **【任意堆】**，拿走 **【1 个】**。

就是这个规则差异，导致了底层数学模型的彻底崩塌。

### 为什么标准 Nim 必须用“异或和 SG”？

**SG 定理有一个极其苛刻的先决条件：各个子游戏必须是【完全独立】的。**
什么是完全独立？就是**“每次操作，你只能选择其中一个子游戏进行改变，绝不能同时影响其他子游戏”。**

在标准 Nim 中，你每次只能选 **1 堆**。
这在逻辑上叫 **“或（OR）”**：我动了 A 堆，就**绝对不能**动 B 堆。
因为这种“严格互斥”的独立性，数学家才证明了：这种独立状态的合并，在代数上唯一对应的运算符就是**异或（$\oplus$）**。

### 为什么这道题【绝对不能】用异或？

回到这道题，规则允许你：**挑选任意多堆，各拿走 1 个。**
这在逻辑上叫 **“与（AND）”**：我可以在同一个回合里，既动 A 堆，**又**动 B 堆，**还**动 C 堆！

**一旦规则允许你跨越“堆”的界限，同时操作多个堆，这些堆就不再是“独立的子游戏”了！**
它们在操作上被物理绑定在了一起。既然失去了独立性，SG 定理的前提就被打破了，**异或（$\oplus$）运算在这里就完全失效、变成毫无意义的乱码了**。

---

### 从实战威力看：你拥有的“上帝权限”不同

我们用一个具体的例子，来看看规则的改变，让你在游戏里拥有的权力发生了多么翻天覆地的变化。

**假设桌上有两堆硬币： `1 和 1`。**

**场景 A：如果在标准 Nim 游戏里（只能动 1 堆，随便拿）**
*   你面对 `1, 1`。异或结果是 `1 ^ 1 = 0`，这是必败态。
*   你只能选其中 1 堆，拿走 1 个。局面变成 `0, 1`。
*   对手拿走剩下的 1 个，局面变成 `0, 0`。你输了。
*   **你的无力感**：你眼睁睁看着两堆都是 1，但你**没有权限**同时消灭它们。

**场景 B：如果在《Another Game》里（可以动任意堆，各拿 1 个）**
*   你面对 `1, 1`。
*   这算必败态吗？**绝不！**
*   因为规则允许你“选任意多堆”，你直接大喊一声：“我两堆全选了！”
*   你同时从两堆里各拿走 1 个。局面瞬间变成 `0, 0`。
*   你直接拿到了最后的硬币，**你赢了！**

**发现了吗？**
在标准 Nim 里，`1, 1` 是死局，异或为 0 是对的。
但在本题里，`1, 1` 是可以直接绝杀对手的必胜局！如果这时候你还去用异或算 `1 ^ 1 = 0`，然后得出必败的结论，这就滑天下之大稽了。

正是因为这道题赋予了你**“同时操作多堆”的上帝权限**，让你拥有了一次性修复所有奇数的终极能力（把所有的奇数堆一起选上，各减 1，瞬间全变偶数）。

---

### 终极总结：如何判断用哪种方法？

以后在算法竞赛中，看到博弈论题目，**第一眼先扫规则**。请牢记这个“分水岭原则”：

1.  **如果规则是“每次只能选择其中 1 堆/1 个部件进行操作”**：
    *   **特征**：各部分严格独立，互不干扰。
    *   **解法**：毫不犹豫，直接上 **SG 函数 + 异或（$\oplus$）**。

2.  **如果规则是“每次可以同时操作多个堆/部件” 或者 “把一堆的东西挪到另一堆里”**：
    *   **特征**：各部分产生了联动，独立性被破坏。
    *   **解法**：**绝对不要用异或！** 抛弃 SG 定理。去寻找整体的**奇偶性（Parity）**、**对称性（Symmetry）**，或者像阶梯博弈那样寻找能抵消的“废动作”。

这道《Another Game》，名字叫“另一个游戏”，其实就是出题人故意设下的一个陷阱，用来惩罚那些不看适用条件、见题就无脑套“异或”公式的选手的！

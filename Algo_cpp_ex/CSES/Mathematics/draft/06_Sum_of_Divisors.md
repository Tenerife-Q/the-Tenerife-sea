# Sum of Divisors

## Problem Description
Let $\sigma(n)$ denote the sum of divisors of an integer $n$. For example, $\sigma(12) = 1+2+3+4+6+12 = 28$.
Given $n$, calculate the sum:
$$S = \sum_{i=1}^n \sigma(i)$$
Your task is to compute $S \pmod{10^9+7}$.

令 $\sigma(n)$ 表示整数 $n$ 的所有正约数之和。例如 $\sigma(12) = 1+2+3+4+6+12=28$。
给定 $n$，计算 $1$ 到 $n$ 中每个数的约数之和的总和：
$$S = \sum_{i=1}^n \sigma(i)$$
并输出 $S \pmod{10^9+7}$。

## Input
The only input line has an integer $n$.

单行包含一个整数 $n$。

## Output
Print $\sum_{i=1}^n \sigma(i) \pmod{10^9+7}$.

输出 $\sum_{i=1}^n \sigma(i) \pmod{10^9+7}$。

## Constraints
* $1 \le n \le 10^{12}$

## Example
**Input:**
```text
5
```

**Output:**
```text
21
```
*(Explanation: $\sigma(1)=1, \sigma(2)=3, \sigma(3)=4, \sigma(4)=7, \sigma(5)=6$. The sum is $1+3+4+7+6=21$.)*

## 核心考点与算法剖析

这道题虽然披着“素数/因子”的外衣，实际上是极为经典的**数论分块（Number Theoretic Block / Integer Division Chunking）**算法模板题。如果不采用分块思维，在 $n = 10^{12}$ 的压迫下，任何 $O(n)$ 或者 $O(n \log n)$ 的解法都会遭受降维打击般的超时 (TLE)。

### 算法一：正向暴力思维 (Brute Force) - 为什么不可行？
最直接的做法是：枚举 $i$ 从 $1$ 到 $n$，对每个 $i$ 用 $O(\sqrt{i})$ 的时间求出它的约数和，然后全部加起来。
- **时间复杂度**：$O(n \sqrt{n})$。当 $n = 10^{12}$ 时，运算量高达 $10^{18}$，宇宙尽头都算不完。

更聪明一点的暴力法：转换视角，不去问“每个数被哪些数整除”，而是去问**“数字 $x$ 作为约数，在 $1 \dots n$ 的区间里出现了多少次？”**
数字 $x$ 出现在 $x, 2x, 3x \dots$ 等它的倍数中。所以在 $1 \dots n$ 这个范围内，$x$ 总共作为约数出现了 $\lfloor \frac{n}{x} \rfloor$ 次！
因此，原公式可以极度优雅地转变为：
$$S = \sum_{x=1}^n \left( x \times \left\lfloor \frac{n}{x} \right\rfloor \right)$$
- **时间复杂度**：只要一层 $O(n)$ 的循环。
- **结论**：然而 $n = 10^{12}$，由于 CPU 每秒运算大约 $10^8$ 次，跑完 $O(n)$ 需要数小时，依然 **TLE**。只能逼迫我们寻找 $O(\sqrt{n})$ 的出路。

---

### 算法二：数论分块结合对称性 - $O(\sqrt{n})$ 本题最优解

我们要计算的是 $\sum_{x=1}^n x \cdot \lfloor n/x \rfloor$。
在 $x > \sqrt{n}$ 之后，$\lfloor n/x \rfloor$ 这个商的值会变得非常小，而且**大段大段的 $x$ 对应的 $\lfloor n/x \rfloor$ 都会是同一个值**！

举个例子：$n = 100$
- $x = 51 \sim 100$ 时，$\lfloor 100/x \rfloor$ 恒等于 $1$。
- $x = 34 \sim 50$ 时，$\lfloor 100/x \rfloor$ 恒等于 $2$。

**数论分块的核心法则**：
既然有一大片连续的 $x$ 区间（设左右端点为 $L$ 和 $R$），它们的“出现次数” $q = \lfloor n/x \rfloor$ 全是一模一样的，我们干嘛还要一个一个去算乘法呢？
对于这个区间，它的贡献和可以直接拉出来：
$$q \times \left( L + (L+1) + \dots + R \right)$$
后面这是一个标准的**等差数列求和**：$\frac{(L + R) \times \text{项数}}{2}$。

#### 跷跷板分界点：$\sqrt{n}$
由于 $x \times \lfloor n/x \rfloor \le n$ 是一对乘积因子关系，故这两个角色中必定至少有一个 $\le \sqrt{n}$！
因此我们将计算彻底劈成两半：
**第一部分（小约数）：** 当约数 $k \le \sqrt{n}$，我们直接用 $O(\sqrt{n})$ 遍历这些约数，每次加上 $k \times \lfloor n/k \rfloor$。
**第二部分（大约数）：** 大约数不好直接遍历，转而**遍历它们出现的次数 $k$**（显然此时次数 $k \le \sqrt{n}$ ）！并且当次数为 $k$ 时，必定对应一段连续的大约数区间，我们利用等差数列一把算完。

## 核心代码变量与数学细节讲解

这里有四个深刻的数学细节：

### 1. 分界点的确定、`n/k` 角色重定义与实例解析

**分界点为什么是 $\sqrt{n}$？（深层数学原理）与为什么不能仅仅 $k \times k \le n$ 收尾？**
如果纯粹遍历每一项约数 $x$，我们需要从 $1$ 一直遍历到 $n$，复杂度是 $O(n)$，会面临严重超时。
当我们把公式转换为 $\sum x \times \lfloor n/x \rfloor$ 时，设出现次数 $y = \lfloor n/x \rfloor$。由向下取整的性质推导可知，**$x \times y \le n$ 必定成立**。

**【数学原理：反证法刻画 $\sqrt{n}$ 的绝对防线】**
假设存在某种极端情况，使得约数 $x$ 和它的出现次数 $y$ **同时**严格大于 $\sqrt{n}$：
即 $x > \sqrt{n}$ 且 $y > \sqrt{n}$。
那么两者的乘积 $x \times y > \sqrt{n} \times \sqrt{n} = n$。这与核心前提 $x \times y \le n$ 产生了绝对矛盾！
**这个数学结论带给我们一个极具统御力的启示：在关于 $n$ 的“约数 $x$”和“次数 $y$”这对乘积关联模型中，永远不可能出现两者双双处于 $>\sqrt{n}$ 的状态。必定至少有一个因子被死死压制在 $\le \sqrt{n}$ 的范围内。**

这就是算法真正的破局点：
1. **第一战场（处理弱者 $x$）**：当这俩数中**约数 $x$ 占据低位**（$x \le \sqrt{n}$）时，我们就平铺直叙地遍历约数 $x$ 来累加，这一步最多循环 $\sqrt{n}$ 次。这就是我们在代码的第一部分写下 `k * k <= n`（即 $k \le \sqrt{n}$）的根本意图。
2. **为何不能就此结束？** 如果只执行这第一部分就收工，**剩下的那批 $x > \sqrt{n}$ 的庞大“大约数”群就全部被遗漏（会导致严重少算数据）**。
3. **第二战场（制裁强者 $x$）**：绝妙之处在于，当面临那些**约数 $x$ 占据高位**（$x > \sqrt{n}$）的情况时，根据上述不讲理的数学定律，与它们配对的**出现次数 $y$ 必定被迫跌落神坛，即 $y \le \sqrt{n}$**！
4. **视角翻转**：因此在第二阶段，我们**果断放弃遍历那些如同星辰大海般的“大约数个体”（这就是引发传统 $O(n)$ 超时的元凶），转而掉转枪口，直接去遍历它们极其稀少且数值可控的“出现次数”（总共不超过 $\sqrt{n}$ 种可能）**。我们将拥有同一个“出现次数”的大约数们包裹压缩成一个连续段落（区间块），然后直接套用等差数列公式以 $O(1)$ 的代价一把求和。

基于这道坚实的数学推断逻辑，我们才确信不能全靠 $O(n)$ 死循环，也不能只写一个 $k \le \sqrt{n}$ 跑路。数论分块用这种曼妙的主客体转化机制，将庞大的搜寻切分成两段最大 $O(\sqrt{n})$ 的旅路并将其平滑拼接，构筑出全局毫无破绽的 $O(\sqrt{n})$ 性能飞跃！

**随着分界点的跨越，代码前后阶段中循环变量 `k` 的角色发生了戏剧性的互换：**
- **第一部分 (小约数遍历)** 中，`k` 是**约数本身**。此时 `n/k` 计算出来的是这个约数在 $1\dots n$ 中发生的**总出现次数**。
- **第二部分 (大约数块的次数遍历)** 中，`k` 彻底变成了**出现的次数**。此时反用 `n/k` 算出来的则是“刚好出现这个次数的**最大约数边界**”。

**【直观可视化思维：抛开公式，为什么 `n/k` 能神奇地锁定边界？】**

如果你觉得代数推导太绕，我们用最直白的“面积/装箱”逻辑来可视化这个过程。
核心大前提永远只有一个：**约数 $x$** $\times$ **出现次数 $k$** $\le n$。

想象 $n=12$ 是一块总面积不能超过 $12$ 的画布：
- **右边界 $R$ 的直观真相：** 
  假设我现在指定，我们要找的这批数字，它们在内部统统**出现了 $k=2$ 次**。
  那么请问，能连续装下 $2$ 次且总面积 $\le 12$ 的数字，**最大**能长多大？
  闭着眼睛算也是 $12 \div 2 = 6$。没有任何魔法！
  这恰恰就是为什么当 `k` 代表次数时，公式依旧是原封不动的 `R = n / k`。它算出的就是**“在满足出现 $k$ 次的前提下，约数所能触及的天花板界限”**。
  同理，如果要求出现 $3$ 次，那数字最大天花板就是 $12 \div 3 = 4$。

- **左边界 $L$ 与“区间缝隙”的诞生：**
  刚才算出了：能塞下 $\ge 2$ 次的最大数字是 $6$；能塞下 $\ge 3$ 次的最大数字是 $4$。
  那请问：**刚好卡在“只能装下 $2$ 次，装不下 $3$ 次”的数字**是谁？
  很显然，就是介于 $4$ 之后、直到 $6$ 的那些数字区间，也就是 $\{5, 6\}$！

  **我们可以画一条数轴来直观切断它：**
  ```text
  [ 数字1, 数字2, 数字3, 数字4 ]   [ 数字5, 数字6 ]    [ 数字7 ~ 数字12 ]
  └────── 最高出现 3次 ──────┘   └──出现 2次 ──┘   └─── 出现 1次 ────┘
           界限 = 12 / 3 = 4          界限= 12/2 = 6       界限= 12/1 = 12
  ```
  看到图形的缝隙了吗？
  当我们在计算出现次数 $k=2$ 的区间时，它的**右端点 $R$** 自然是 `12 / 2 = 6`。
  它的**左端点 $L$** 怎么求？不就是上一种状况（能够出现 $k+1=3$ 次的势力范围终点）往右挪一步吗！
  所以左边起点 $L$ 顺理成章地等于 `(12 / 3) + 1 = 5`。转换成代码就是极为精炼的：`L = n / (k + 1) + 1`。

这就是空间挤压产生区间的直观原理！通过降阶看待除法本身具备的“最高容量”容斥特性，我们自然而然就把那些大体积的约数，用小频次给一块块“框”出来了。

### 1.1 分界点的确定与变量角色互换（深层数学定理与几何证明）

**为什么分界点偏偏是 $\sqrt{n}$？为什么偏偏在这里互换 $k$ 的含义？**

这里隐藏着解析数论中极其著名的定理级方法——**狄利克雷双曲线法（Dirichlet's Hyperbola Method）**。

#### 几何可视化：双曲线下的整点计数
我们把原公式 $S = \sum_{x=1}^n x \times \lfloor n/x \rfloor$ 在笛卡尔二维坐标系中画出来。
令横轴为 $x$（约数），纵轴为 $y$（出现在的次数）。
我们其实是在求解满足 $x \times y \le n$ 的第一象限内的**面积属性 / 整点权值**。

$x \times y = n$ 这条线是一条**标准的反比例函数双曲线**。
现在，我们画一条过原点的 45度斜线：**$y = x$**。
这条 $y=x$ 的斜线与 $x \times y = n$ 的双曲线**刚好交汇于一点**。这个交点坐标是谁？
显然是 $x \times x = n \implies x = \sqrt{n}, y = \sqrt{n}$。

**这就是 $\sqrt{n}$ 作为绝对分界点不可撼动的数学根基！**
这条斜线 $y=x$ 像一把手术刀，把双曲线下方的区域完美劈成了两半，这也正是狄利克雷定理的核心策略：
1. **左上区域（高耸入云）：** 在交点 $\sqrt{n}$ 的左侧，$x$ 很小（$x \le \sqrt{n}$），但 $y$ 很高很大（$y > \sqrt{n}$）。
2. **右下区域（扁平伏地）：** 在交点 $\sqrt{n}$ 的右侧，$x$ 很大（$x > \sqrt{n}$），但 $y$ 被极度压缩，变得很小很矮（$y \le \sqrt{n}$）。

#### 为什么在这里产生角色“神级切换”？

既然图象在 $\sqrt{n}$ 处展现了**彻底的对称性**，我们就可以玩弄维度操作：
- **第一阶段（扫荡左半边高楼）：** 我们沿着横轴（约数轴）走，走过 $x=1, 2, 3 \dots \lfloor\sqrt{n}\rfloor$。在这个阶段，变量 `k` 指代的就是横轴的 **约数 $x$**。因为最多只有 $\sqrt{n}$ 步，我们走得很轻松。这就是代码第一阶段循环 `k * k <= n` 的本质！

- **撞到交点 $\sqrt{n}$ 之后，向右看：横轴太长了（从 $\sqrt{n}$ 绵延到 $n$），这会引发 $O(n)$ 级别的地狱级超时！**

- **第二阶段（对右半边实行“降维打击”）：** 右半边虽然横轴巨长，但是纵轴（次数轴）极度萎缩矮小啊！它最高最高也不会超过 $\sqrt{n}$！
  所以，数学家们下达了一个惊天逆转指令：**把脖子扭转 90 度，我们不看横轴了，我们顺着纵轴（次数轴）往上爬！**
  这就解释了为什么变量的定义能瞬间无缝丝滑切换！在第二阶段，循环变量 `k` 脱胎换骨，它不再代表横轴庞大杂乱的 $x$，而是代表了纵轴极其迷你的 **次数 $y$**。而纵轴的取值范围，正好也是从 $1$ 到 $\lfloor\sqrt{n}\rfloor$。

**总结定理结论：**
因为 $x \times y \le n$ 的双曲对称性，导致了无论哪一边，**“小的那个维度的长度永远不会超过 $\sqrt{n}$”**。
我们在 $\sqrt{n}$ 这个黄金分割点，果断抛弃了发散的一维（长长的约数轴），转头去遍历收敛的另一维（低矮的次数轴）。
这种**“打不过长的横轴，就把图形翻转去量短的纵轴”**的几何重构思想，就是数论分块能在 $\sqrt{n}$ 处进行绝地转换，从而实现 $O(\sqrt{n})$ 时空碾压的最强理论底座！

**随着分界点的跨越，代码前后阶段中循环变量 `k` 的角色发生了戏剧性的互换：**
- **第一部分 (小约数遍历)** 中，`k` 是**约数本身 (走横轴)**。此时 `n/k` 计算出来的是纵向的高度（出现次数）。
- **第二部分 (大约数块的次数遍历)** 中，`k` 彻底变成了**出现的次数 (走纵轴)**。此时反用 `n/k` 算出来的则是横向的宽度（刚好出现这个次数的最大约数边界）。

**具象化表格分析：以 $n=12$ 为例（分界点 $\lfloor\sqrt{12}\rfloor = 3$）**
我们来看看程序是如何依靠边界效应分阶段巧妙计算的：

| 计算阶段 | 循环变量 $k$ 代表什么？ | $k$ 取值 | 实际对应的约数 / 区间 | $\lfloor n/x \rfloor$ (出现次数) | 这一步计算的贡献累加和 |
| :--- | :--- | :---: | :--- | :---: | :--- |
| **第一阶段** | **约数本身** | 1 | 约数 $= 1$ | 12 次 | $1 \times 12 = 12$ |
| **第一阶段** | **约数本身** | 2 | 约数 $= 2$ | 6 次 | $2 \times 6 = 12$ |
| **第一阶段** | **约数本身** | 3 | 约数 $= 3$ | 4 次 | $3 \times 4 = 12$ |
| --- | --- | --- | *** 前后交接分界，开始用块处理大约数 *** | --- | --- |
| **第二阶段** | **出现的次数** | 3 | 约数区间：$[4, 4]$ | 3 次 | $(4) \times 3 = 12$ |
| **第二阶段** | **出现的次数** | 2 | 约数区间：$[5, 6]$ | 2 次 | $(5\!+\!6) \times 2 = 22$ |
| **第二阶段** | **出现的次数** | 1 | 约数区间：$[7, 12]$ | 1 次 | $(7\!+\!8\!+\!\dots\!+\!12) \times 1 = 57$ |

*观察表格边界效应可以发现*：在跨入第二阶段后，块的处理威力被成倍放大（比如次数为 $1$ 时，跨度直接从 $7$ 包揽到了 $12$），数论分块硬生生将原本要分别算的庞大步骤压缩成了一次等差求和（最后求出 $12\!+\!12\!+\!12\!+\!12\!+\!22\!+\!57 = 127$），将 $O(n)$ 一举压缩成了 $O(\sqrt{n})$！

### 2. 区间边界划分与防止重叠计算
第一部分的条件是 $k^2 \le n$（即小约数 $\le \sqrt{n}$）。
第二部分虽然次数也是 $\le \sqrt{n}$，但条件必须写成 `n/k > k`！这意为：“我要找的最大约数上界，必须超过我在第一部分已经亲手算过的那个 $\sqrt{n}$”。
这块“防火墙”绝对杜绝了同一数字被第一部分和第二部分重复计算两次的悲剧。

### 3. 取模意义下的除法 (计算乘法逆元)
等差数列中有除以 $2$ 的操作：$\frac{(L+R) \times (R - L + 1)}{2}$。
在模运算中，**不能直接执行除法**！要把除以 $2$ 改成乘以 **2 对于模数 $10^9+7$ 的乘法逆元**。
设逆元为 $x$，定义式：$2 \times x \equiv 1 \pmod{10^9+7}$
显然 $2 \times 500000004 = 1000000008 \equiv 1 \pmod{10^9+7}$。
因此在代码里，原本的 `/ 2` 将替换为 `* 500000004 % MOD`。

## 究极压行与防溢出代码实现

```cpp
#include <iostream>

using namespace std;

// 1e9 + 7
long long MOD = 1000000007;

// 2 在模 10^9+7 下的乘法逆元
long long INV2 = 500000004;

// 给定连续数列左右端点，计算等差数列和：(L + R) * 项数 / 2
// 注意：每次乘法后都必须进行 % MOD，防止爆 long long 溢出！
long long sum_sequence(long long l, long long r) {
    long long cnt = (r - l + 1) % MOD;        // 项数
    long long sum_LR = (l + r) % MOD;         // 首项 + 末项
    long long res = (cnt * sum_LR) % MOD;     // (联乘)
    return (res * INV2) % MOD;                // 乘以逆元等效于除以 2
}

int main() {
    // Fast I/O
    ios_base::sync_with_stdio(false);
    cin.tie(NULL);

    long long n;
    if (!(cin >> n)) return 0;

    long long total_sum = 0;

    // 第一部分：处理 <= √n 的“小约数”
    // 此时 k 本身代表约数的大小。
    long long k;
    for (k = 1; k * k <= n; ++k) {
        long long occur_times = n / k;
        // 把这个数产生的和加入结果
        // 因为可能有多次相加操作，内部也要取模
        long long current_val = (k % MOD) * (occur_times % MOD) % MOD;
        total_sum = (total_sum + current_val) % MOD;
    }

    // 第二部分：处理 > √n 的“大约数”
    // 这些大约数拥有一个共同特征：它们在 1~n 范围内的出现次数很少。
    // 所以，我们转而遍历它们出现的“次数”！此时 k 代表出现的次数。
    for (k = 1; n / k > k; ++k) {
        // 次数为 k 的这些大约数，有一个连续的右边界 R
        long long R = n / k;
        
        // 它们必然也要有一个左边界 L
        // 因为次数比 k 大1 的右边界是 n / (k + 1)
        // 所以当前这一批次的左边界就是 (n / (k + 1)) + 1
        long long L = n / (k + 1) + 1;
        
        // 我们在第一部分已经处理完所有的 “<= 小部分约数边界” 
        // 为了防止重复计算，我们要确保算的大约数 L 必须严于第一阶段的边界
        long long max_small_divisor = -1;
        // 退回第一阶段计算后的 k 位置，找到第一阶段算到的真正最后的小约数
        long long small_d = 1;
        while (small_d * small_d <= n) {
            small_d++;
        }
        small_d--; // 找到最大的 <= √n 的数字
        
        // 事实上，上面 L 已经能天然隔离，只要和第一阶段对接
        // 我们取 max 确保不要把第一部分算过的重新算进去
        if (L <= small_d) {
            L = small_d + 1;
        }

        // 如果左边界被挤压导致比右边界还大，那就证明这段不合法，直接不计算即可
        if (L <= R) {
            // (L...R) 这段里面所有数字作为约数，统统在 1~n 里出现了 k 次！
            // 所以我们求这批数字的等差数列和，然后统一乘以批次 k
            long long seq_sum = sum_sequence(L, R);
            long long block_val = (seq_sum * (k % MOD)) % MOD;
            total_sum = (total_sum + block_val) % MOD;
        }
    }

    cout << total_sum << "\n";

    return 0;
}
```

### 教练话语总结
整除分块在 $10^{12}$ 的数论题目中是神一般的存在。将原本不可逾越的 $O(n)$ 拉回了极为快速的 $O(\sqrt{n})$。彻底领悟“小数字以元素枚举，大数字以块组枚举（反转出现次数）”以及逆元除法的使用，是这道题留给算法竞赛生最纯粹的设计美学体现！

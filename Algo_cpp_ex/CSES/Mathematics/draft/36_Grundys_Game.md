# Grundy's Game

## Problem Description
There is a heap of $n$ coins and two players who move alternately. On each move, a player chooses a heap and divides into two nonempty heaps that have a different number of coins. The player who makes the last move wins the game.
Your task is to find out who wins if both players play optimally.

有一堆包含 $n$ 枚硬币的硬币堆，两名玩家轮流行动。在每一步行动中，玩家选择一堆硬币并将其分成两个大小不同且非空的硬币堆。进行最后一次移动的玩家赢得游戏。
你的任务是找出在双方都采用最优策略的情况下，谁会赢得游戏。

## Input
The first input line contains an integer $t$: the number of tests.
After this, there are $t$ lines that describe the tests. Each line has an integer $n$: the number of coins in the initial heap.

第一行输入包含一个整数 $t$：测试用例的数量。
之后有 $t$ 行描述测试用例。每行包含一个整数 $n$：初始硬币堆中的硬币数量。

## Output
For each test case, print "first" if the first player wins the game and "second" if the second player wins the game.

对于每个测试用例，如果先手玩家获胜则输出 "first"，如果后手玩家获胜则输出 "second"。

## Constraints
$1 \le t \le 10^5$
$1 \le n \le 10^6$

## Example
**Input:**
```
3
6
7
8
```

**Output:**
```
first
second
first
```

这是一道极为经典的**组合博弈论题（Combinatorial Game Theory）**，甚至这个游戏本身就以博弈论奠基人之一 —— Sprague-Grundy 定理中的 P.M. Grundy 名字命名，被称为 **Grundy's Game**。

在上一题《Nim Game I》中，我们知道了任何“独立堆的多局游戏”最后都可以转化为**异或和**。而在此题中，我们将揭示如何利用 **SG函数（Sprague-Grundy Function）** 以及其中的 **mex（Minimum Excluded value）运算**，将任何这种看似复杂的“拆分局面”，全部等效降维成最基本、最普通的 Nim 石子堆游戏。

下面为你详细解析 SG定理的数学原理，以及推导公式！

### 一、 核心逻辑与 SG 函数理论

在 Grundy's Game 中，游戏规则是：将一堆 $n$ 枚硬币分成两堆**大小不同**且**都不为0**的硬币：$k$ 和 $n-k$（其中 $k \neq n-k \Rightarrow k < n/2$）。
分成两堆后，这就相当于变成了两堆**全新的、独立的游戏**。这个过程可以一直递归下去。

根据 **Sprague-Grundy (SG) 定理**，任何一个处于公平组合游戏（Impartial Game）状态 $x$ 的必定等效于一个规模为 $SG(x)$ 的普通 Nim 石子堆。这个定理可以说是现代博弈论的核心引擎！

而 $SG(x)$ 是如何得到的呢？它是通过一个极其精妙的算子得到的——**`mex` 算子 (Minimum Excluded value)**。

**什么是 `mex`？**
给定一个非负整数集合 $S$，`mex(S)` 指的是**不属于集合 $S$ 的最小非负整数**。
* 例子：$mex(\{0, 1, 3\}) = 2$；$mex(\{1, 2\}) = 0$；$mex(\{\}) = 0$。

**SG 函数推导公式**：
对于一个状态 $x$，如果它能转移到的子状态集合为 $\{y_1, y_2, \ldots, y_m\}$，那么 $x$ 的 SG 值为：
$$SG(x) = mex(\{ SG(y_1), SG(y_2), \ldots, SG(y_m) \})$$

在这道题里，一堆硬币 $n$ 会被一分为二，变成两堆独立的新硬币，分别是 $k$ 和 $n-k$。
**关键定则**：多个独立游戏的组合（合成局面），它的整体 SG 值等于各个子游戏 SG 值的**按位异或和（XOR）**！
也就是说，被拆分后的新局面 $\{k, n-k\}$ 的 SG 值，等效于：$SG(k) \oplus SG(n-k)$。

因此，Grundy's Game 中，针对一堆硬币 $n$，它的状态转移与 SG 值公式极其优美：
$$SG(n) = mex \Big( \{ SG(k) \oplus SG(n-k) \mid 1 \le k < \frac{n}{2} \} \Big)$$

---

### 二、 从宏观理解为什么是 `mex` 和 `XOR`？

如果你觉得上面的公式像凭空降临的天书，不妨我们联系现实，回到我们在《Nim Game I》中体会过的“平衡（0）”与“失衡（非0）”。

#### 1. 为什么用 `mex`（最小未出现非负数）？
回想组合博弈的底层原理：
*   **必败态（输）**：无论如何只能转移到必胜态。因为无法转移到必败态（哪怕是一个），这就表示它能转移到的集合 $S$ 中**绝对没有 $0$**（必败）。既然不可能有 $0$，那么不属于 $S$ 的最小非负数自然就是 $0$ 了。这完美印证了公式：必败态必定有 $SG(x) = 0$ 且 $mex(S) = 0$。
*   **必胜态（赢）**：只要能转移到至少一个必败态（哪怕只有一个）。既然在这个集合 $S$ 中包含了 $0$，那么 $0$ 已经被占用了。因为 $0 \in S$，不属于集合 $S$ 的最小非负整数肯定不再是 $0$。这完美印证了公式：只要你能抵达必败态，你自己的 SG 即 $mex(S) > 0$，所以你必胜！

为什么非得是紧凑的数字 `mex` 操作？因为在合并不同游戏时，这为异或提供了等效连续映射的空间。

#### 2. 为什么用异或和（XOR）合并？
回想在《Nim Game I》里，我们拆穿了：独立堆在进行操作时，本质上是在做二进制的“对称维持与破坏”。如果把分开的两小堆硬币看成独立的桌子上的两堆 Nim 石子，这不正是我们要算的“整体合并后的异或值”吗！

因此，如果你把一堆大的 $n$，拆成了两个完全不相关的 $k$ 和 $n-k$，那对于下一名玩家而言，面对的其实就是一个包含 $(k)$ 和 $(n-k)$ 的标准的初始 Nim 游戏了。它的总效果值理所当然的就是 $SG(k) \oplus SG(n-k)$。

### 三、 手摇推导：感受 SG 值是如何长出来的

根据公式 $SG(n) = mex \{ SG(k) \oplus SG(n-k) \mid 1 \le k < n/2 \}$，由于没有可行的移动方案（只能分出非空且大小不同的堆），在 $n=1, 2$ 时的 SG 肯定全是 $0$。
我们来实际推演几个看看：

*   $n = 1, 2$ 时：**无法拆分成两堆大小不同且非空的堆**，无合法操作，集合为空 $S=\{\}$。
    $SG(1) = SG(2) = mex(\{\}) = 0$（先手必败）。
*   $n = 3$ 时：必须分成 $\{1, 2\}$。
    唯一操作局面的异或和为 $SG(1) \oplus SG(2) = 0 \oplus 0 = 0$。转移集合为 $\{0\}$。
    $SG(3) = mex(\{0\}) = 1$（先手必胜。果然！先手把 3 分成 1 和 2 之后对手面对双全是 0 的情况，死路一条）。
*   $n = 4$ 时：必须分成 $\{1, 3\}$（不能分 $\{2, 2\}$ 因为要求大小不同）。
    异或和为 $SG(1) \oplus SG(3) = 0 \oplus 1 = 1$。转移集合为 $\{1\}$。
    $SG(4) = mex(\{1\}) = 0$（先手必败，因为你唯一的方法是制造出 SG=1，这会变成必胜态拱手让给对手）。
*   $n = 5$ 时：可以分 $\{1, 4\}, \{2, 3\}$。
    方案一 $\{1, 4\}$: $SG(1) \oplus SG(4) = 0 \oplus 0 = 0$
    方案二 $\{2, 3\}$: $SG(2) \oplus SG(3) = 0 \oplus 1 = 1$
    转移集合为 $\{0, 1\}$，所以 $SG(5) = mex(\{0, 1\}) = 2$。

这就是 SG 定理极具魅力的地方，所有繁复至极的不同选择树，最终收敛在这个小小整数里面。只要最终推出来的 $SG(n) > 0$，你就是先手必胜 (`first`)，否则就是后手必胜 (`second`)。

### 四、 代码的 O(1) 魔术与数学悬案

如果你看一看我写的 C++ 预演代码，你会发现它并没有把这个 DP 生成过程做到底，而是加上了一句硬切断判定：**`if (n >= 2000) cout << "first";`**

你可能会想：等一下，不用计算了吗？难道大于 2000 就永远赢？为什么？

这就涉及到了 Grundy's Game 在数学界的一个尚未被 100% 严谨证明的**著名悬案（经验定理）**。
通过上面的 SG 递推公式，我们可以借助计算机穷举所有的结果：
* 随着 $n$ 递增，得到的 $SG(n)$ 的值序列是：
  0, 0, 1, 0, 2, 1, 0, 2, 1, 0, 2, 1...
* 在它缓慢无序地跳跃波动时，人们发现 $SG(n) = 0$ 的数字变得越来越稀少。
* 在穷尽了海量数据之后，数学家和程序员们得到了一个令人吃惊的结论：
  **自 $n = 1222$ 以后，Grundy 序列中的 $SG(n)$ 就再也不会出现 0 了！** 并且它甚至表现出了一种周期间隔的伪随机性态。

换句话说，只要硬币数 $n \ge 1222$ 时，由于 $SG(n) > 0$ 恒成立，它的状态**永远不包含必败节点 0**，也就是说，只要堆数庞大，**先手总是能找到办法剥取部分制胜点，先手永远立于不败之地！**

这也就赐予了算法竞赛者一个极为粗暴绝佳的偷袭武器：既然此题中 $t \le 10^5, n \le 10^6$，常规跑所有的异或 `mex` 的时间复杂度是 $O(n^2)$ 的，放在 $10^6$ 铁定超时。
但是有了这个神秘数字 $1222$，我们真正需要去运算计算 $SG$ 值的，只有 $n \le 2000$ 那些小测试数据而已。超出边界的一律大胆直接输出 `first` 即可，代码的空间和时间被这一个惊艳的世界真相压缩到了极致！

这种数学上带有“悬疑而笃定”的巧合特性，也正是在刷组合博弈相关算法题目时，带给我们独特震撼和趣味的源泉之一。

### 五、 参考题解与代码实现 (Solutions)

#### Solution 1: 暴力计算 SG 值 (O(N^2))
令 $\text{grundy}[x]$ 表示包含 $x$ 枚硬币的堆的 SG 也就是 Grundy 值，并令 $\oplus$ 表示异或（XOR）运算符。
当我们把一堆 $x$ 枚硬币分成 $a$ 和 $b$ 两堆时，会产生两个子游戏，它们的 Grundy 值分别是 $\text{grundy}[a]$ 和 $\text{grundy}[b]$。因此，移动后的整体 Grundy 值为 $\text{grundy}[a] \oplus \text{grundy}[b]$。

为了计算 $\text{grundy}[x]$，我们遍历将 $x$ 枚硬币分成两堆的所有可能方式，计算每种移动后的 Grundy 值，然后求它们的 `mex` 值（即未出现在这些数字中的最小非负整数）。

这个方案是正确可行的，但由于它的时间复杂度是平方级的 $O(N^2)$，而 $N$ 高达 $10^6$，所以直接运行会超时 (Too slow)。不过，我们可以借此代码来研究问题的规律。

```cpp
#include <iostream>
#include <set>
using namespace std;
const int N = 1000000;
int grundy[N + 1];

int main() {
    for (int i = 1; i <= N; i++) {
        set<int> s;
        for (int j = 1; i - j > j; j++) {
            s.insert(grundy[j] ^ grundy[i - j]);
        }
        grundy[i] = 0;
        while (s.count(grundy[i])) {
            grundy[i]++;
        }
    }

    int t;
    cin >> t;
    for (int ti = 1; ti <= t; ti++) {
        int n;
        cin >> n;
        cout << (grundy[n] ? "first" : "second") << "\n";
    }
}
```

#### Solution 2: 利用数学悬案性质的 O(C) 优化
通过研究 Solution 1，我们可以发现 $1222$ 是最后一个 Grundy 值为 $0$ 的状态（即后手必胜态 losing position）。因此，只需要计算状态 $0 \dots 1222$ 的 Grundy 值，因为只要硬币数大于 $1222$，我们就总是能赢。

需要注意的是，我们的搜索仅仅证明了在 $0 \dots 10^6$ 范围内 $1222$ 是最后一个必败态。不过目前已知在 $0 \dots 2^{35}$ 的巨大范围内这也成立。至于在这之后是否还有必败态，依然无人知晓。

```cpp
#include <iostream>
#include <set>
using namespace std;
const int N = 1222;
int grundy[N + 1];

int main() {
    for (int i = 1; i <= N; i++) {
        set<int> s;
        for (int j = 1; i - j > j; j++) {
            s.insert(grundy[j] ^ grundy[i - j]);
        }
        grundy[i] = 0;
        while (s.count(grundy[i])) {
            grundy[i]++;
        }
    }

    int t;
    cin >> t;
    for (int ti = 1; ti <= t; ti++) {
        int n;
        cin >> n;
        bool win = n > N || grundy[n];
        cout << (win ? "first" : "second") << "\n";
    }
}
```

### 第一步：亲自上手玩（从小数字开始找必赢的办法）

**游戏规则**：把一堆硬币分成两堆，必须**不一样多**。谁最后分不了，谁就输。

我们把硬币数量从 1 开始，一点点往上加。

#### 场景 1：桌上有 1 个硬币 （你先手）
*   你看了看，1 个硬币怎么分成两堆？分不了。
*   **结局**：你没法动，你直接**输了**。
*   **结论**：**1 个硬币是必败局。**

#### 场景 2：桌上有 2 个硬币 （你先手）
*   你想分成两堆，只能是 1个 和 1个（1+1）。
*   但是规则说“两堆必须不一样多”！所以 1+1 是违规的。
*   **结局**：你没法动，你**输了**。
*   **结论**：**2 个硬币是必败局。**

#### 场景 3：桌上有 3 个硬币 （你先手）
*   你能分吗？能！唯一合法的分法是：**1 个和 2 个（1+2）**。
*   你分完之后，桌子上现在有两堆硬币：一堆是 1，一堆是 2。
*   轮到对手了。对手看着桌子上的 1 和 2，根据我们刚才在场景 1 和 2 的推论，1 不能分，2 也不能分。
*   **结局**：对手没法动，对手输了。也就是**你赢了**！
*   **结论**：**3 个硬币是必胜局。**

#### 场景 4：桌上有 4 个硬币 （你先手）
*   你怎么分？4 只能分成 1+3 或者 2+2。因为 2+2 一样多违规，所以你**被迫只能分成 1+3**。
*   你分完后，桌子上有两堆：1 和 3。
*   轮到对手了。对手看着 1 和 3，1 不能动，他**只能动那个 3**。
*   根据场景 3 的经验，对手把 3 分成了 1+2。
*   现在桌子上变成了三堆：1，1，2。
*   轮到你了。你看着这三堆，全都是不能动的死局。你没法动。
*   **结局**：你**输了**。
*   **结论**：**4 个硬币是必败局。**

#### 场景 5：桌上有 5 个硬币 （你先手）
重点来了！这是第一次你拥有了**选择权**。
你可以分成：**1+4**，或者 **2+3**。
作为绝顶聪明的你，会选哪条路？
*   如果你选 **2+3**：桌上剩下 2 和 3。对手动不了 2，但他会动 3！根据刚才的经验，谁拿到 3 谁就能赢。你把 3 给了对手，等于**送人头**。
*   如果你选 **1+4**：桌上剩下 1 和 4。对手动不了 1，他被迫只能动 4。根据我们在场景 4 的经验，谁面对 4 谁就得死。你把 4 扔给了对手，**对手必死**！
*   **结局**：你果断选择分成 1+4，对手面对 4 无路可走，**你赢了**！
*   **结论**：**5 个硬币是必胜局。**

### 第二步：逻辑链条断裂的危机（为什么简单的 W 和 L 不够用了？）

看！只要硬币少，我们完全可以靠穷举法，一步步推断出：
1(输), 2(输), 3(赢), 4(输), 5(赢)。

**但是，当硬币增加到 7 个的时候，人类的大脑会瞬间宕机。**
为什么？我们来试试 7 个硬币。

*   你可以分成：**1+6**，**2+5**，**3+4**。
*   假设你分成了 **3+4**。
*   现在桌子上同时存在一堆 3，和一堆 4。
*   我们已知：3 是“必胜（W）”，4 是“必败（L）”。
*   那么请问：**桌子上同时放着一个必胜局和一个必败局，这个时候，面对桌子的那个人，到底是赢还是输？？？**

这就是逻辑断裂的地方！
当游戏每次只是拿走硬币（堆数不变）时，我们只需要知道输赢（W/L）就够了。
**但这个游戏会分裂！一堆变两堆，两堆变三堆。当桌子上同时出现好几堆的时候，简单的“输赢”两个字，已经无法评估整体局面的好坏了！**

### 第三步：引入“战斗力评分系统”（破局之法）

为了解决同时面对多堆硬币的问题，数学家说：我们不能简单地用“输/赢”来标记一堆硬币，我们需要给每堆硬币评一个具体的**“战斗力星级（SG值）”**！

*   **0 星（SG=0）**：纯废物，没法动，或者动了必死。（对应输 L）
*   **1 星（SG=1）**：战斗力弱，它只能变成 0 星扔给对手。（对应赢 W）
*   **2 星（SG=2）**：战斗力强，它可以选择变成 0 星，或者变成 1 星扔给对手。（对应更稳的赢 W）

有了星级，我们怎么评估桌面上有多堆硬币的情况？
这里直接使用结论：**把所有硬币堆的星级，进行“异或（^）”运算，算出的结果，就是整个桌面的总星级！** （这就是异或在这里存在的唯一实际意义：它是唯一能正确合并星级的计算器）。

### 第四步：实战演练“评星级”（重走 1 到 5）

现在我们用星级系统，重新打一遍 1 到 5，你会发现极其丝滑：

*   **1个硬币**：没法分。也就是没法走到任何星级。
    **评级**：连 0 星都变不出来，说明它缺 0。它就是 **0 星 (SG=0)**。

*   **2个硬币**：不能分。没法变。
    **评级**：缺 0。也是 **0 星 (SG=0)**。

*   **3个硬币**：只能分成 1+2。
    1 是 0星，2 是 0星。合并总星级：`0 ^ 0 = 0`。
    说明 3 个硬币能且只能把局面变成 0 星。
    **评级**：它能变出 0，但变不出 1。说明它缺 1。它就是 **1 星 (SG=1)**。

*   **4个硬币**：只能分成 1+3。
    1 是 0星，3 是 1星。合并总星级：`0 ^ 1 = 1`。
    说明 4 个硬币只能把局面变成 1 星。
    **评级**：它能变出 1，但它**变不出 0 星直接绝杀对手**！它缺 0。它就是 **0 星 (SG=0)**。
    *(看！4 个硬币是个废物，因为它没法绝杀，完美印证了之前手动推导的必败！)*

*   **5个硬币**：分成 1+4，或者 2+3。
    如果分 1+4：1 是 0星，4 是 0星。合并星级 `0 ^ 0 = 0`。
    如果分 2+3：2 是 0星，3 是 1星。合并星级 `0 ^ 1 = 1`。
    说明 5 个硬币，既能变出 0 星，也能变出 1 星！
    **评级**：它能变出 0 和 1，它缺 2。它就是 **2 星 (SG=2)**。

*(注：上面这个“看它缺什么星，它就是什么星”的过程，就是你一直觉得很抽象的 `mex`。它其实就是一个找缺口的评级规定而已！)*

### 第五步：逻辑大闭环（如何看懂代码）

通过上面的“具体玩游戏”和“星级评估”，现在我们再串联起这道题的所有逻辑，你一定会豁然开朗：

1. **怎么赢？**
   我要确保留给对手的是一个**“0 星局（总 SG=0）”**，对手就必死。
2. **怎么算星级？**
   因为一堆硬币会被劈成两堆，为了评估这两堆凑在一起的威力，必须用**异或（^）**把它们加起来。
3. **怎么定级？**
   看一堆硬币能变出哪些下一级的星级，找出它**“变不出来的最小星级（缺口）”**，这就是它的真实星级。找缺口这个动作，就叫 **`mex`**。

那段官方代码，其实就是一台不知疲倦的机器人。它从 1 开始，不停地重复我们在“第四步”里的操作，把每一堆硬币的星级全算了出来存到 `grundy` 数组里。

最后，只要查一下 `grundy[n]` 是不是 0 星。如果是 0 星，先手就输；如果大于 0 星（1星、2星...），先手必赢。

从亲自拿着硬币推导输赢，到发现多堆硬币无法评估，再到引入星级系统，最后用代码自动打星。顺着这条线想，晕眩感有没有减轻一点？
